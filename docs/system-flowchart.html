1

系統總覽

一張圖看完整條路:資料來源 → 解析 → 三大判別 → 加權裁決 → 使用者輸出;人工修正沿底部紫色軌道回流訓練資料庫,再回頭更新模型 — 系統會越用越準。

2

使用流 — 拿來即時推論的路徑

設計師/業務上傳後,系統自動判斷並產出推薦做工、尺寸表與 PDF;人是最後一關,在 Prototype 編輯頁確認與調整,而每一筆修正都會被記錄下來餵回訓練。

3

訓練流 — 標準答案怎麼建立、怎麼回流

從清理資料表開始,建立 Golden Sample 金標、定義標準答案,餵進模型訓練,再用 L1/L2 評分把關;未達標的部分由人工補充,修正結果回流成下一輪訓練資料,形成閉環。

4

三大判斷來源與加權裁決

流程圖不只畫資料流,也要畫「系統怎麼判斷」:三個判別來源各有擅長與現況準確率,加權裁決決定誰優先、誰補強、什麼情況交給人工。

圖像辨識

60%

判什麼:部位、口袋、門襟、剪接線等視覺項目

現況:模型準確率約六成,需持續訓練

做工翻譯(文字解析)

80%

判什麼:老師傅做工語句,依 Golden Sample 與規則庫解析

現況:整體準確率約八成

信心指數

90%

判什麼:用大數據比對補強,約九成可跑出

現況:在圖像或翻譯不確定時作為覆蓋依據

5

資料來源與缺口

讓 MIS 一眼看懂:資料從哪裡來、哪裡缺資料、誰要補。琥珀色即目前缺口。

資料來源串接狀態已有目前缺口下一步/窗口
KPAC/Judy 翻譯平台 API 已串接 可用翻譯資料約 900+ 款 早期資料缺款號 評估補款號方式
MTM API 已綁 NKCSO/SSO 款式基本資料(JSON) JSON 欄位不完整 下週 review,與 Zack 確認缺欄位
POM/TagPack 尺寸表 未結構化 多為 PDF 文件 缺結構化欄位 確認是否有 POM grading、tolerance 資料
StyleTricks/MTM Patch 評估中 — 可補欄位待確認 評估作為補齊欄位的第二支 API
Golden Sample 標準答案庫 建置中 部分金標 覆蓋率不足 訓練流核心資料,持續擴充(見第 3 節)
6

MIS 待確認事項

這張藍圖的目的之一就是跟 MIS 對齊技術面,以下五組問題請在會議中逐一確認。

M1系統部署與版控

  • GitHub 是否要移到公司 GitLab?
  • 公司資安環境如何串接?

M2API 權限與認證

  • NKCSO/SSO 的授權流程
  • API token 如何核發與管理
  • 欄位層級的權限如何劃分

M3自動 Trigger

  • 新款入庫是否自動啟動分析?
  • 由哪個系統觸發?
  • 觸發後跑哪些流程?

M4資料回流

  • 使用結果如何回到訓練資料庫?
  • 人工修正如何被記錄?
  • 是否形成新的 Golden Sample?

M5算力與環境

  • 是否需要地端模型?
  • 是否需要公司內部 GPU/伺服器?
  • Celtrix 對外服務與內部訓練是否共用資源?
